# OneHope Resource Centre

AI-powered resource assistant for OneHope Uganda.
Built with FastAPI (Python), a TF-IDF search index, the Google Drive API and Groq-hosted LLMs.

---

## How it works

```
User message (frontend, signed in with Google)
        ↓
POST /chat  (FastAPI backend — verifies the Google token, rate-limits per user)
        ↓
Search index → up to 6 relevant passages, typo-tolerant,     [no API call]
               PDF/PPTX duplicates removed
        ↓
Sheet catalogue → resources whose titles match (incl. videos) [cached 30 min]
        ↓
Groq LLM called with question + passages + catalogue matches  [1 API call]
        ↓
Answer + source links (only documents the model actually saw)
```

**Result: 1 LLM call per user message, regardless of library size.**

## Local setup

```bash
cd onehope-backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env              # then fill in the values
```

For local development without Google Sign-In, set `AUTH_DISABLED=true` in `.env`.
**Never set this on the production server.**

**To get `GOOGLE_SERVICE_ACCOUNT_JSON` as one line:**
```bash
python3 -c "import json; print(json.dumps(json.load(open('service_account.json'))))"
```

### Index your documents

```bash
python indexer.py
```

This fetches the Google Sheet, downloads and extracts text from every supported file,
skips videos, audio and images, and writes `search_index.json`. Whole documents are
indexed (up to `MAX_CHARS_PER_DOC`, default 400,000 characters each), not just the first pages.

### Run the server and tests

```bash
uvicorn main:app --reload    # http://localhost:8000
pytest                       # runs the test suite
```

Then open `onehope-frontend/index.html` (set `BACKEND_URL` in `app.js` to `http://localhost:8000`).

## Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `GROQ_API_KEY` | ✅ | Groq API key |
| `SHEET_CSV_URL` | ✅ | Published CSV link of the resource sheet |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | ✅ for indexing | Service account with Viewer access to the Drive files |
| `GOOGLE_CLIENT_ID` | ✅ in production | OAuth client ID for Google Sign-In. If missing, the API refuses requests |
| `ALLOWED_DOMAIN` | optional | Only allow accounts from this domain, e.g. `onehope.net` |
| `ADMIN_EMAILS` | optional | Comma-separated emails allowed to trigger a re-index |
| `ALLOWED_ORIGINS` | recommended | Comma-separated frontend URLs allowed by CORS, e.g. `https://onehope.netlify.app` |
| `RATE_LIMIT_PER_MINUTE` | optional | Messages per user per minute (default 10, `0` disables) |
| `GROQ_MODELS` | optional | Comma-separated model fallback order (defaults to current Groq production models) |
| `MAX_CHARS_PER_DOC` | optional | Max characters indexed per document (default 400000) |
| `AUTH_DISABLED` | local dev only | `true` skips sign-in entirely |

## Supported file types

| Type | Indexed |
|---|---|
| PDF, .docx, .pptx, .xlsx | ✅ |
| Google Docs, Slides, Sheets | ✅ |
| Video, audio, images | ⏭ Text not extracted — still found by title via the sheet catalogue |

## API endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/` | public | Health check |
| GET | `/me` | signed in | Current user's email and whether they are an admin |
| GET | `/index-status` | signed in | Index size and whether a re-index is running |
| POST | `/chat` | signed in | Main chat endpoint |
| POST | `/reindex` | admin | Start a background re-index of the Drive documents |

### POST /chat

Request:
```json
{
  "message": "Where can I find the Africa Manual?",
  "conversation_history": [
    {"role": "user", "content": "Hello"},
    {"role": "model", "content": "Hi! How can I help?"}
  ]
}
```

Response:
```json
{
  "answer": "The OneHope Africa Manual v2.1 covers...",
  "sources": [{"file_name": "OneHope Africa Manual v2.1.pdf", "drive_url": "https://drive.google.com/...", "folder": "Manuals"}],
  "suggestions": ["...", "...", "..."],
  "needs_clarification": false
}
```

## Keeping the index up to date

The backend re-indexes automatically every night at **2:00 AM server time**.
Admins (listed in `ADMIN_EMAILS`) can also click **Refresh Index** in the sidebar.

| Change | Picked up |
|---|---|
| New row in the Google Sheet | Within 30 minutes (title catalogue), full text after next re-index |
| New or edited file in Drive | Next nightly re-index, or manual refresh |

> On Render's free tier the filesystem resets on each deploy, so a re-index done on
> the server is lost at the next deploy. Run `python indexer.py` locally and commit
> `search_index.json` to keep a durable copy. **Keep the repository private** — the
> index contains the text of OneHope's internal documents.

## Troubleshooting

**`Sign-in is not configured on the server` (503)** → set `GOOGLE_CLIENT_ID` on the server (or `AUTH_DISABLED=true` locally).

**`Only administrators can refresh the index`** → add the email to `ADMIN_EMAILS`.

**`The AI service is busy`** → every Groq model in the fallback list failed; check the server logs and your Groq quota.

**Garbled file names (`ð…`)** → re-run `python indexer.py`; the sheet is now always read as UTF-8.

**Files not being indexed** → the service account email needs **Viewer** access to the Drive files, and the Drive API must be enabled.
